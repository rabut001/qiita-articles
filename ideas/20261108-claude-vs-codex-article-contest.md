# Claude Code 対 Codex 「記事ネタ出しから記事の反響まで」勝負の記録

状態: アイディア(勝負の進行中に記録を取る。記事化は勝負の結果が出てから)

## 一言

同じリポジトリ群を材料に、Claude Code と ChatGPT/Codex にそれぞれ記事のネタ出しを依頼し、**作成した記事の反響が大きい方**を今後の記事作成のパートナーにする。この勝負そのものを記事にする。

過去の「Claude Code vs Codex」(2026-10-25、アプリ開発の比較)の続編にあたる。あちらは「作ったものの比較」、こちらは「書いた記事の反響の比較」。

## 勝負のルール(2026-11-08 に確定)

### 評価式

```
スコア = 閲覧数 + (LGTM + ストック) × 100
```

- 閲覧数・LGTM・ストックは、Qiita 上の値を使う。閲覧数は本人の認証付き API で取得する。
- 集計期間:**公開後1か月間**(公開から30日後、720時間後の値)。
- 係数100の根拠:
  - 過去の新規記事5本は、1か月時点で反応(LGTM + ストック)が0〜3件、閲覧数が120〜840だった。
  - 係数50では、反応3件でも+150にしかならず、ほぼ閲覧数だけの勝負になる。
  - 過去の「反応1件あたりの閲覧数」は中央値で約1,090。係数100は、その約10倍の重みを反応に与える。反応は閲覧数より希少で、内容への意思表示でもあるため妥当と判断した。
  - 例:記事A(800 views、反応0)と記事B(500 views、反応3)は、係数100で引き分け、係数50ではAの勝ち。

### 運用上の注意

- **計測のタイミング**:公開から30日後(720時間後)の値。`qiita-dashboard` の毎朝4時台のスナップショットのうち、最も近いものを使う。
- **公開日時の揃え方**:相手と公開時期が離れると、曜日や時期で有利不利が出る(平日の閲覧は土日の約3倍)。揃える努力をする。
- **数値の取り方**:両方とも Qiita 上の表示値を使う。
- **勧誘の禁止**:知人に LGTM やストックを頼まない。反応の重みが大きい式なので、数件の依頼で結果が動く。
- **式の固定**:公開前に決め、結果を見てから変えない。

- 最高は 1,138。この水準を超えれば、自作記事の中では上位。
- 反応は外れ値で決まる傾向がある(LGTM の52%が1記事)。勝敗が運に左右される可能性が高い。

## 記事にするときの切り口の候補

1. **勝負の設計**:式の決め方、係数の根拠(過去データとの照合)、運用ルール。事前に決める理由。
2. **結果と、運の要素**:1本対1本の勝負は、外れ値と公開時期の影響が大きい。その点を数字で振り返る。
3. **予測の答え合わせ**:公開前に書いた30日後の予測と、実績の差。
4. **ネタ出しの比較**:両者が出したアイディアの違い。出てきた案、過去記事との重複、採用理由。

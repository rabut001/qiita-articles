# 執筆スタイルガイド

既存記事(2023-10〜2026-10 の28本)から抽出した、編集方針の目安。必須の規則ではなく、迷ったときの基準として使う。

## 構成

- 冒頭に「この記事は何か」を置き、動機と結論を先に書く。結論は「先に結論を言うと **…**」のように太字の一文で示してもよい。
- 結びは短くてよい。まとめの節は必須ではない。
- 関連する自分の記事があれば、冒頭か末尾でリンクする。

## 文体

- 敬体(です・ます)を基本にする。
- 根拠の強さに応じて、断定と留保(「多分」「(かも)」)を使い分ける。確認していないことは断定しない。
- 一人称は「私」。立場(DB屋など)を示す書き方は、読者が文脈をつかむ助けになる。

## 誤りと未解決の扱い

- 解決できなかった問題は、そのまま書く。
- 後から分かったこと、訂正は、日付つきの「追記」で残す(例: 【2024/12/30追記】)。

## 体裁

- 見出しは `#` から始め、階層を飛ばさない(`#` の直下に `####` を置かない)。
- コードブロックには言語を指定する。
- 画像は `articles/<slug>/images/` に置き、`draft.md` では相対パスで書く(公開時に完全 URL へ変換する)。

## 公開前の点検

- タグの綴り(余分なカンマや空白、typo)とタイトルの前後の空白。
- コードブロックの言語指定の有無。
- 見出し階層の飛び。
- 以上は変換スクリプトの検査項目にする。

# 28本・142日の日次データで分かった、閲覧数とLGTMは別物だった

状態: アイディア(GAS版データで初回集計済み。深掘り前)
作成日: 2026-11-08

## 一言

自分の Qiita 記事28本の日次スナップショット(閲覧数・LGTM・ストック)から、**どんな記事がどう伸びたか**を記述する。「こう書けば伸びる」という処方ではなく、1人の書き手の実データから見えたことを、分からなかったことも含めて書く。

## 想定読者

- Qiita の投稿者(自分の記事の反応を、数字でどう読むか知りたい人)

## 使うデータ

- `ideas/data/Qiita Dashboard - snapshots.csv`(GAS版。コミットしない)
- 2026-06-14〜2026-11-08の142日分、28記事、3,549行。毎朝4時台に取得。
- 欠測:6/26〜7/1、7/15〜7/17、10/12〜10/14。
- 合計:144,122 views / LGTM 61 / ストック 58。

## 言えること(自分の28本・142日の範囲で)

1. **閲覧数と LGTM・ストックは別物**
   - 閲覧数の上位6本(VS2022オフライン 23,264、SQL Serverコスト 21,803、正規化 13,090、Docker/WSL 12,707、M365ライセンス 11,957、pgAdmin/ODBC 11,525)で全体の約65%。その LGTM は0〜6。
   - LGTM 32・ストック 25 の「DB設計がアプリの品質を上げる(かも)」は 5,019 views で9位。
2. **LGTM・ストックは外れ値で決まる**
   - LGTM 61のうち32(52%)、ストック58のうち25(43%)が1記事。
   - 142日の間に増えた LGTM は全28本で+7、ストックは+2だけ。
3. **2つの伸び方**(新規7本のみの観察。サンプルは小さい)
   - AI・ツール系は初日〜1週間で横ばい。「プロンプトを全部公開」は初日332→14日480→60日553。「Claude Code vs Codex」は初日107→3日334→7日409→14日454。
   - SQL・環境系は長く伸びる。「UNION」は初日41→14日200→60日333。
   - 新規7本のうち最も伸びたのは「AI時代のデータベース、何が変わる？」(7日593、60日1,126)。
4. **古い記事が流入を支える**
   - 直近30日の閲覧(5,388)の約69%は、上位8本の旧記事。日平均は約195(6月272 → 10月208)。
   - 公開からの平均が高いのは、VS2022オフライン 1,558/30日、M365ライセンス 1,418、pgAdmin/ODBC 624、SQL Serverコスト 589。DB設計は 458。
   - VS2022(日45→23)、M365(日39→19)のように秋に半減した記事もある。原因は不明。
5. **平日に読まれる**
   - 平日は日約250〜320、土日は約110。計測が毎朝4時台のため、差分は前日分として読み替えた。
6. 突発的な急増は、正規化の記事の2026-08-14(+181、通常は日24前後)だけ。原因は不明。

## 言えないこと・外れた仮説

- 「他人の記事への反応記事だから LGTM が付いた」は**否定された**。DB設計記事の参照元(「『返金処理』はPATCH？…」)の LGTM は2だった。
- DB設計記事が伸びた理由は不明。要ヒアリング(SNS での共有、Qiita での掲載など)。
- 28本・1人のデータなので、処方にはできない。記述にとどめる。
- 閲覧数の定義(重複・ボットの扱い)は Qiita 側の仕様で不明。公開時期が違うため、古い記事ほど累積が大きい。

## 記事の形(案)

- 構成:データの紹介(取得のしくみは簡潔に)→ 閲覧数の内訳 → LGTM・ストックの偏り → 2つの伸び方 → 平日/土日 → 分からなかったこと。
- 追加案:次に公開する記事の30日実績を公開前に予測して書いておき、結果と照らす(続編にする)。

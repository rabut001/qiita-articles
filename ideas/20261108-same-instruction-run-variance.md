# 同じ指示を何度も出して分かった、AIエージェント比較で語ってよいこと

状態: アイディア(簡易計測のみ。深掘り前)
作成日: 2026-11-08

## 一言

`project-manager-training-1〜6` は、同じ指示を Claude Code と Codex に3回ずつ与えた6回分の成果物。2026-10-25 の記事は `-5` と `-6` の1回ずつの比較で、末尾に「プロンプト一発での比較なので限界」とある。**その限界に、残りの4回分のデータで答える**。

想定される結論:単発の比較で語ってよいのは、**複数回で再現した軸だけ**。再現しない軸は、ツールの性格ではなく run ごとの揺れかもしれない。

## 6回分の条件(各 README の記載)

| リポジトリ | ツール | モデル・モード |
|---|---|---|
| -1 | Codex | GPT-6.1 Sol・high(1回目) |
| -2 | Claude Code | Opus 5.5・high |
| -3 | Codex | GPT-6 Astra・high |
| -4 | Claude Code | Opus 5.5・middle |
| -5 | Codex | GPT-6.1 Sol・high(2回目) |
| -6 | Claude Code | Sonnet 5.5・high |

モデルとモードが揃っていない点は、記事の冒頭で明示する。

## 簡易計測の結果(2026-11-08、GitHub API のツリー情報)

| 指標 | Codex(-1 / -3 / -5) | Claude Code(-2 / -4 / -6) |
|---|---|---|
| テストファイル数 | 2 / 3 / 3 | 0 / 1 / 1 |
| ソースコード量(KB) | 41 / 54 / 54 | 54 / 55 / 54 |
| 文書量 md(KB) | 77 / 35 / 56 | 41 / 43 / 34 |
| AGENTS.md / CLAUDE.md(KB) | 2.0 / 1.7 / 1.2 | 2.4 / 2.8 / 13.4 |

- ツールごとに再現:テストの厚さは3回とも Codex が上。10/25 の記事の「テストは Codex」はこの指標で再現。
- 再現しない:ソースコード量はほぼ同じ。文書量と AGENTS.md の大きさは、同じツール内でもばらつく(特に `-6` の13.4KB)。
- Codex の `-1` と `-5` は同じモデル・同じ指示で、改善提案の内容が大きく違う(`-1` の README に記載。原因は不明)。

## 注意・限界

- 指標は粗い。テストファイルは名前の規則で数えただけ。UI の良し悪し、解説の質、燃費は見ていない。
- モデルが同一ではない(Claude 側は Opus と Sonnet が混在)。
- 燃費(利用枠の消費)はリポジトリの記録から再計測できない。
- 結論が「どちらが優れる」ではなく「単発比較を信用しすぎるな」になる。ツール比較を期待する読者には地味に映る。

## 深掘りでやること

- 指標を増やす(E2E テストの件数、検証スクリプトの数、解説の文字数、コミット数、ディレクトリ構成)。
- 10/25 の記事の各主張(UI、構成、解説、ソース、テスト)を、他の run でも言えるかで仕分ける。UI は実際に起動して確認が必要。
- 実測値は commit を固定して記録する(research.md)。
